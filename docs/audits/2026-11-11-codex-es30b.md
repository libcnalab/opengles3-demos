# ES 3.0 demo audit — group B

Audited all 16 assigned demo directories against `AUDIT_BRIEF.md`, the demo brief, validation policy, known limitations, and Khronos ES/GLSL text. The full project built successfully in `/tmp/audit-es30b-build` with `-j 1`. All shaders in this group use `#version 300 es`; every manifest feature and GLSL feature ID resolves in the inventories. The known deviations I reviewed match normative rules and use driver-specific matching supported by the documented evidence. Corrupted program-binary calls run in isolated child processes.

## Findings

- **BUG —** [post-processing/main.cpp](demos/es30/post-processing/main.cpp:1280). At 333×777, probe selection finds zero lamp pixels and fails the validation check, although the remaining checks pass; the same demo passes at 256×256. The audit criterion says: “validation must PASS on a valid render at every size.” Make the scene/probe layout retain at least one visible lamp at tall aspect ratios, with a non-vacuous pixel check.
- **BUG —** [sync-objects/main.cpp](demos/es30/sync-objects/main.cpp:63). `cell_rect` floors each cell to `w/4` by `h/4`; at 333×777 the grid scans only 332×776 pixels, so the exact whole-image coverage assertion fails. The brief requires the layout to fill any window and validation to pass at every size. Partition with per-cell endpoints `floor(i*size/4)` and `floor((i+1)*size/4)` so remainder pixels belong to a cell.
- **BUG —** [texture-3d-and-arrays/main.cpp](demos/es30/texture-3d-and-arrays/main.cpp:592). `add_fetch` does not set the texture-boundary dimensions, so `probe()` does not skip boundary samples for these `texelFetch` panels. At a 41-pixel panel width, boundary-aligned fragment centers cause 41 mismatches in panels 16 and 45 at 333×777; both pass at 256×256. The brief explicitly says: “Where a sample lands on a texel or edge boundary, accept either neighbour instead of skipping the pixel.” Set boundary dimensions for fetch panels and accept either adjacent texel at those coordinates (or skip them while preserving the minimum non-vacuous probe count).
- **BUG —** [transform-feedback/main.cpp](demos/es30/transform-feedback/main.cpp:833). The particle-cell check hard-codes a 900-pixel minimum. A valid 333×777 render covers 890 pixels in that cell and fails only this threshold; it passes at 256×256. The brief requires validation to pass at every valid size. Derive the lower bound from the cell dimensions/particle coverage, or adjust the layout so the intended minimum remains achievable at narrow widths.

## Run evidence

Using llvmpipe with `--headless --validate --width 333 --height 777`, 11 demos passed, the four findings above failed, and the multisample default-framebuffer demo was blocked by the unavailable 4-sample pbuffer. Re-running the four failing demos at 256×256 passed all checks (38/38, 69/69, 117/117, and 182/182 respectively). No source files were changed; this report is the only worktree addition.
