# ES 3.1 demo audit report

Audited the 15 directories assigned in the phase 6 brief. The fresh debug build completed with `-j 1`. The configured CTest matrix passed **105/105** runs (GPU, llvmpipe, zink at es-max/es-min, plus ANGLE native). Additional validated runs passed at 333×777 (`compute-basics`, `framebuffer-no-attachments`) and 640×480 (`texture-gather`).

## Findings

### `framebuffer-no-attachments`

- **WEAK** — [main.cpp:1289](demos/es31/framebuffer-no-attachments/main.cpp#L1289), also stated in [README.md:111](demos/es31/framebuffer-no-attachments/README.md#L111). The check hard-fails if `dFdx(gl_FragCoord.x)` or `dFdy(gl_FragCoord.y)` differs from 1 by more than 0.01. GLSL ES 3.10 §8.13 says an implementation “may approximate the true derivatives by using a fast but not entirely accurate derivative computation”; it gives no accuracy bound and permits the method to differ per fragment. This is implementation-dependent behavior, not a conformance requirement. **Fix:** keep the helper-invocation and side-effect checks normative and passing/failing, but print the measured derivatives as observations instead of making the 0.01 threshold a hard check. The observed Mesa result was exact in this run, which is empirical evidence only.

## Clean demos

- `atomics` — Verified exact atomic counter and memory results, resource queries, defined error cases, and CPU-checked compaction; normative claims cite GLSL ES 3.10 / ES 3.2.
- `compute-basics` — Verified work-group built-ins, limits and boundaries, defined dispatch/link errors, buffer results, and image layout against the CPU model.
- `compute-indirect-and-to-render` — Verified indirect commands and dispatches through readback, barrier-dependent consumers, CPU image comparisons, and defined invalid-command errors.
- `compute-particles` — Verified the float error bound is derived from GLSL ES 3.10 §4.7.1, exact integer state and spawn count, guard range, negative controls, and rendering probes.
- `compute-shared-memory` — Verified shared-memory reductions and scans against integer CPU models, including barrier variants and negative controls.
- `image-load-store` — Verified image formats, dimensions, layered and fragment accesses, coherency, and readbacks. The 3D slice case that can fault ANGLE/RADV is isolated in a child; the Mesa format deviation is recorded in `KNOWN_LIMITATIONS.md` and matched to Mesa.
- `indirect-draw` — Verified generated indirect commands, rendered results, and transform-feedback error differences according to the reported ES version; the Mesa ES 3.1 deviation is version-gated and documented.
- `multisample-textures` — Verified all stored samples by per-sample fetch, sample-mask effects, and multisample state; sample positions and edge coverage are not asserted. ANGLE error deviations are recorded and narrowly matched.
- `program-interface-query` — Verified queried interface properties against shader declarations and used queried layouts in execution. Mesa and ANGLE deviations are recorded in `KNOWN_LIMITATIONS.md`.
- `program-pipelines` — Verified pipeline state, stage composition, uniforms, and draw results. The Mesa/ANGLE pipeline deviations are represented by separate matching substrings and documented.
- `separate-vertex-format` — Verified separate format/binding state, integer attribute data, pixel results, and limit claims. The 64-bit offset deviation is documented for Mesa and ANGLE.
- `ssbo-std430` — Verified std430 layout and runtime array behavior through shader writes and buffer readback, with negative controls. Mesa/ANGLE deviations are recorded.
- `stencil-texturing-and-level-queries` — Verified depth/stencil sampling and texture-level queries against allocated state. Its ANGLE-specific deviations are recorded.
- `texture-gather` — Verified gather ordering, wrap modes, offsets, swizzles, shadow and integer samplers, completeness rules, and GLSL ES 3.20-only `textureGatherOffsets` gating.

No unrecorded known-deviation claims, es-min conformance overclaims, desktop GL calls, extension substitutions, or shader-version mismatches were found in this group. The inspected deviation substrings and cases agree with the entries in `docs/KNOWN_LIMITATIONS.md`. The worktree had no source changes before this report was created.
