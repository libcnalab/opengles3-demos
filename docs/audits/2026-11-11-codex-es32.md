# ES 3.2 demo audit report

Scope: the 12 assigned `demos/es32/` directories. Read the project audit brief, validation policy, demo brief, known limitations, meta-gl gaps, handoff, and Khronos ES 3.2 / GLSL ES 3.20 text. Configured and built with the requested meta-gl source and `-j 1`.

## Findings

### `cube-map-array`

- **BUG** — [main.cpp](demos/es32/cube-map-array/main.cpp:603), [main.cpp](demos/es32/cube-map-array/main.cpp:1633): at 333×777 on llvmpipe, validation fails `78/79`; the environment-map probe found no pixels on spheres 0 and 4 (sphere probe counts `0, 1138, 2205, 1116, 0`). The capture clips the two end spheres at the left and right edges. The view keeps a 45° vertical FOV while using the portrait viewport aspect for a fixed five-sphere row. **Project rule:** “The picture must fill the surface at any size” and validation must pass at other sizes. **Fix:** adapt camera distance/FOV or sphere spacing to the viewport aspect, and retain an assertion that all five spheres have clean probes.

### `float-targets-and-indexed-blend`

- **BUG** — [main.cpp](demos/es32/float-targets-and-indexed-blend/main.cpp:1249): `compose_window()` always sets a 256×256 viewport, and `validate()` reads only that 256×256 region. At 333×777 the demo passes `161/161` checks, but its capture shows the picture in the lower-left 256×256 block and clears the rest of the window. **Project rule:** “The picture must fill the surface at any size.” **Fix:** compose to the actual surface dimensions and scale/reflow the panels; validate the entire window using those dimensions.

### `geometry-shaders`

- **WEAK** — [main.cpp](demos/es32/geometry-shaders/main.cpp:1381): the test hard-fails when a geometry program exceeding `MAX_GEOMETRY_TOTAL_OUTPUT_COMPONENTS` links successfully, and XFAILs that outcome on Mesa. ES 3.2 §11.3.4.4 says: “LinkProgram will fail if it determines that the total component limit would be violated.” This conditions the required failure on the implementation determining the violation; it does not explicitly require every conformant linker to diagnose every statically computable product. The check therefore treats a conditional rule as guaranteed. **Fix:** report successful linking as an implementation observation, or cite stronger normative text that requires detection before keeping it as a hard conformance check.
